# ISCMS — Records Officer: Findings Log

Manual review (screenshots), role: Records Officer (Agnes Nantege). Complements ISCMS-HR-Manager-Findings.md, ISCMS-GM-Dashboard-Findings.md, ISCMS-Role-Based-Test-Plan.md.

Overall take: the Identity Cards module itself is the strongest-built screen reviewed so far — clear stats, a sensible status filter (Pending/Issued/Revoked), and a genuinely useful table. The issues here are mostly duplication and role-scoping leftovers, not a broken design.

---

## Findings Log

| # | What's off | Why it matters | Severity | Suggested fix |
|---|---|---|---|---|
| R1 | The Identity Cards page renders **two** near-identical hero banners stacked back to back — "Official Personnel Identity Card Issuance" and "Employee Identity Card Issuance & Printing" — each with its own copy of the same three stats (Total Roster 12, Pending ID 2, Active Cards 9) | This is the clearest case of "unnecessary wording" you flagged — two banners saying the same thing in slightly different words, with duplicated stat cards directly beneath each other. Reads as if two versions of the same header got left in during a rebuild | Significant | Delete one banner entirely. Keep a single header + one description line + one stat row. |
| R2 | Both banners' body text covers the same three facts in different words ("capture the holder photo and signature... sign as the issuing Records Officer... prepare the high-security PVC card" / "the Records Officer verifies their biodata, captures the holder photo and signature... prints the high-security PVC card") | Verbose, repetitive phrasing that doesn't add information the second time — just re-describes the same three steps | Minor | Once R1 is fixed (one banner), tighten to a single plain-language line: e.g. "Verify biodata, capture photo & signature, then print the ID card." |
| R3 | Records Officer's home dashboard shows the same "Disciplinary Actions" panel (with full case detail — David Ssempijja, Ronald Kato) that's shown to HR Manager and HR Assistant | Records Officer's job is ID issuance and file archiving — disciplinary finalization isn't part of their chain at all. Showing full case detail to a role that can't act on it is dashboard clutter, and arguably shouldn't be visible to them at all given it's meant to stay within a defined chain (Investigations Officer → Regional Manager → Operations Manager → HR Manager) | Significant | Remove this panel from the Records Officer's dashboard entirely. |
| R4 | "Guard Lifecycle & ID Issuance" panel on the Records Officer's dashboard has a guard-select dropdown with no visible action beneath it — no stage-move controls (unlike the HR Manager/Assistant version). Its description text still reads "Ops/RM move stages; HR records termination; Records Officer issues ID cards" — three different roles' jobs in one line, only the last third of which is theirs | This looks like a stripped-down leftover of the shared component rather than something built for this role — it does nothing, while describing tasks that mostly aren't the Records Officer's. Actual ID issuance already has its own dedicated, well-built page | Significant | Remove this panel from the Records Officer's dashboard entirely — it's redundant with the Identity Cards page and doesn't function as shown. |
| R5 | Guard Deployment Pipeline kanban (recruit intake → training → deployed) also appears on the Records Officer's dashboard | ID issuance/archiving doesn't require visibility into recruitment-to-deployment progress — this is Operations/HR territory, not Records | Minor / Polish | Apply the same "does this help this role decide something" rule used elsewhere — likely remove or replace with something Records-specific (e.g. a "pending ID issuance" count, which the Identity Cards page already shows better). |
| R6 | HR nav dropdown's "Identity Cards" menu item has a badge label that's visibly truncated: "PHOTO · SIGNATURE · P..." | Cut off mid-word in the navigation itself, before the user has even opened the page | Minor / Polish | Shorten the badge text (e.g. "PHOTO · SIGNATURE") or drop it — the destination page already explains what it does. |
| R7 | **RESOLVED** — "Recruitment & Staffing" and "Performance Reviews" don't belong as full nav items for the Records Officer | Records Officer doesn't need either module's working detail — they need each module's *output* to reach them as a narrow trigger. Recruitment: the Identity Cards page's existing "Pending Records Issuance" queue already does this — a newly enrolled guard should land there automatically, no separate Recruitment nav needed. Performance Reviews: confirmed a promotion changes the guard's printed designation, so a completed review that changes designation should trigger a "reissue required" entry in that same Pending queue — Records Officer needs the fact that a card is now outdated, not the review itself (no scores, no comments, no case detail) | — | Remove both nav items entirely. Route both triggers (new enrollment, designation-changing promotion) into the existing Identity Cards "Pending" queue as the single place Records Officer checks — one workflow instead of two extra modules they'd otherwise have to monitor. |

## What's working well (worth preserving, not just fixing what's broken)
- The Identity Cards table's status filter (All / Pending Records Issuance / Issued & Active / Revoked-Suspended) is a genuinely good pattern — it's the kind of "surface what's actionable" filtering the Guard Lifecycle widget (H2, other file) is missing.
- "System User Account — (Provisioned by IT)" column is a nice touch — it's honest about a dependency on another department rather than hiding it.
